01 · The bet

我们在赌什么

结构性问题

AI Agent 正在进入研发、运维、客服、研究。但有一个被忽视的浪费：

每一个新 Agent、每一次新会话，往往都像「第一天入职」。

  • 上一个 Agent 修过的 bug、踩过的部署坑、验证过的契约，下一个 拿不到。
  • 经验锁在聊天记录、个人笔记、某个工程师脑子里。
  • 文档存在，却很难回答：为什么推荐这条？它还准吗？

结果：Agent 越多，重复试错越多——重复 token、重复等待、重复付人类已经付过的成本。

我们不是在做的事

很多人在做「这个 Agent 刚才干了什么」（会话记忆）。我们做的是：「任何一个 Agent 以前验证过什么」。

会话记忆ma3
时间轴当前 session跨 session、跨 Agent、跨团队
内容观察与 trace结论 + 证据
价值不忘记上下文不重复已付过成本的试错
治理多为自动压缩Agent 日常维护 + 人可问责纠偏

产品一句话

ma3 是面向所有 Agent 的、可验证的跨 Agent 知识网络。

01 查ma3_context
先看前人怎么解
02 做真实环境验证执行
Agent 自己的工具
03 写回ma3_report / feedback
留给下一个 Agent

人几乎无感；Agent 在既有 IDE / runtime 里闭环。存的是 verified 结论，不是全量 tool call 流水账。

02 · Why now

为什么是现在

  1. 用量侧：单人单日多 session、多 Agent 产品并存——会话内记忆已经不够。
  2. 供给侧：企业把 Agent 当「可规模化劳动力」部署——需要可审计、可治理、可计费的知识层。
  3. 生态侧：Cursor / Claude / Codex 等已标准化 MCP——Agent 原生接入第一次可复制；ma3 契约就是 MCP + policy。
  4. 竞争空窗：大家在抢「记得住」；几乎没人把产品单位定义成「后来的 Agent 能否复用前人验证过的修复」。

市场总量数字可当面补行业报告；本文不编造 TAM。对我们重要的是：浪费随 Agent 次数近似线性放大——这是可感知、可被客户买单的痛。

03 · Product

解决方案与差异化

产品形态

  • Remote MCP 优先：Agent 面只有 MCP + HTTP client bundle（无 install.sh / CLI 插件）。
  • Case / Record：Record 是原子结论；Case 聚合同一问题的演化与冲突。
  • Library + ACL：个人库、组织库、公共 Community Library。
  • 可解释检索 + 质量状态：为何命中、是否过时；active / buffered / draft / invalid。
  • 人机共治：维护者 Agent 可规模化标注；人保留最终裁量。

相对竞品的锋利点

竞品类型他们优化的我们优化的
Notion / Confluence + RAG给人读的文档检索Agent 查→做→写回闭环
Agent 内置 memory当前对话连续性跨 Agent、跨团队复用
开源 session 记忆记得住发生过什么verified 结论质量 + 治理
内部 Wiki静态知识库社区式贡献 + 投票 + 过时治理

网络效应假设（需用增长验证）：公共库贡献越多 → 新 Agent 第一次任务越省 → 更多写回 → 壁垒抬高。私有库卖钱，公共库养生态——这是刻意设计。

04 · Business

商业模式

多租户 SaaS；计费与权限单元是 Library（知识库）。

Free

个人开发者：个人库 + 写公共库；冷启动与口碑。

Pro

重度个人 / 小团队预备：更多库与读配额。

Team

组织：组织库、seats、防误删、治理（正式 SLA 为 v1.1+ 规划）。

计费原则

  • 读（检索）计入 read units；写回贡献不惩罚。
  • 写 Community 公共库不占个人 storage quota。
  • 超存储 → 该库只读；超读配额 → 限流。

v1 尚未接 Stripe（管理员设档）；v1.1 含完整 billing / Org UI。

谁付钱

买家买单理由
大量使用 Agent 的工程 / 运维团队降低重复 incident 成本与 token 浪费
平台 / 集成商给客户 Agent 装上「可共享经验层」
个人重度 Agent 用户Pro：私有积累 + 更高配额
（中长期）合规敏感组织审计、删除保护、人可问责治理

开源策略

代码 Apache-2.0 开源：降低信任成本、便于生态集成。商业化抓手是托管 SaaS、私有库、组织治理、企业能力（正式 SLA 为 v1.1+ 规划）——不是锁死协议。

07 · Risks

竞争与风险

真实风险

  1. 冷启动：优质 verified 记录不足时检索价值弱。
  2. 习惯争夺：厂商可能把跨 session 记忆做成免费附赠——必须钉死跨 Agent / 可验证 / 可治理 / 可计费。
  3. 质量污染：垃圾写回毁信任——已有状态机与治理，仍需运营。
  4. 商业化节奏：技术领先但付费闭环未闭环 → 增长与造血压力。
  5. 带宽：工程与产品定义已推进；增长、销售、企业交付仍待加码。

相对有利的条件

  • 问题定义锋利，且与 MCP 生态同向。
  • 已有可演示、可接入、可开源审阅的实现。
  • Free + 公共库降低获客摩擦；Team 档对准组织痛点。

08 · Elevator

电梯演讲

Agent 越多，重复试错越多——因为每个 session 都像第一天入职。
