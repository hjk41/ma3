# ma3 v3.1 root UI and polish design

Date: 2026-05-21  
Scope: replace `/ui` with `/` as the only browser UI entry, then fix the UI issues found in the candidate review of `ma3-v3-1-cand-20260520-133611`.

## Product decisions

1. `/` is the canonical and only UI mount point.
2. `/ui` and `/ui/*` are not compatibility paths. They should return the normal API 404 instead of redirecting or aliasing.
3. MCP is unchanged. `/mcp` remains the Streamable HTTP JSON-RPC endpoint, and `/mcp/info` remains metadata.
4. API/doc routes remain API/doc routes and must not be swallowed by the browser SPA:
   - `/mcp`, `/mcp/info`
   - `/healthz`
   - `/v2/*`, `/v3/*`
   - `/auth/*`
   - `/libraries*`
   - `/client/*`
   - `/agents.md`, `/install.sh`, `/install.ps1`
   - `/metrics`
5. Browser deep links are supported only for known UI pages:
   - `/`
   - `/me`
   - `/libs`
   - `/libs/{library_id}`
   - `/keys`
   - `/admin`
   - `/observatory`

## Routing design

### Frontend

- Vite `base` becomes `/`.
- React Router no longer uses `basename="/ui"`.
- All internal links stay root-relative, e.g. `/libs`, `/keys`, `/admin`.

### Backend

- `routes_ui.py` serves the SPA for the explicit UI paths above.
- Do not mount `StaticFiles` at `/`; a root mount can shadow API paths.
- Serve static build assets from a non-conflicting path generated by Vite. With Vite `base: '/'`, assets are requested from `/assets/...`; mount only `/assets` to the web build assets directory.
- Remove `/ui` routes.
- Auth defaults change to root:
  - `/auth/login` default `next="/"`
  - `/auth/callback` default `return_to="/"`
  - `/auth/logout` redirects to `/`

## UI fixes

### Deploy identity and hidden text

Problem: server-injected deploy banner and `sr-only` text are visible because Tailwind does not see classes injected from Python.

Design:

- Keep deploy identity visible for operators, but render it as a compact styled strip above the SPA.
- Add a small inline CSS block from `routes_ui.py` so `.deploy-banner`, `.dep-cell`, `.dep-label`, `.dep-value`, and `.sr-only` do not depend on Tailwind scanning.
- Remove the old keyword/test-only span from visible HTML. If a screen-reader-only heading/link is retained, it must be truly hidden.

### Dashboard and anonymous state

- Anonymous state explains both human SSO and API-key based agent access.
- Login CTA returns to `/`.
- Authenticated dashboard shows task cards: search/context, libraries, API keys, observatory, admin when allowed.
- Effective libraries list has an empty state.

### Libraries and library detail

- Library list has an empty state.
- Library detail becomes knowledge-first:
  1. Library summary card.
  2. Records / cases preview and search guidance.
  3. Members & ACL management for admins.
- Replace the v3.1 placeholder with a real read-only records preview fetched from `/records?library_id=<id>&limit=5` when available. If the API shape does not support it, show a clear “preview unavailable” message instead of placeholder copy.
- ACL role order is `reader`, `writer`, `admin`.
- Role edits show a saved/saving/error status.
- Destructive remove actions are visually secondary until confirmed.
- Legacy principals are labeled as legacy tokens with explanatory helper text.

### API keys

- Keys page uses a clear empty state.
- Create key modal includes:
  - label
  - optional scope selector based on effective libraries
  - optional expiry timestamp
  - copy-once warning for the returned raw secret
- Raw secret is shown in a warning block after creation, not as an unlabelled `pre`.

### Admin console

- Audit table uses humanized labels and relative time where practical.
- Repeated admin-assumption rows are not treated specially in v3.1 code yet, but the table should at least be readable and payload expansion-ready.
- Backup tab highlights degraded status with a yellow/red health badge and remediation text.
- Raw backup keys are humanized, with raw key names kept secondary.
- Bulk xyz keys explain that one username per line is expected and that raw secrets are returned once.

### Observatory

- Humanize metric labels.
- Distinguish “no distribution metric emitted yet” from a zero value.
- Keep values copyable/readable while avoiding raw snake_case as primary labels.

## Acceptance tests

Backend tests:

- `GET /` returns HTML shell.
- `GET /me`, `/libs`, `/libs/<id>`, `/keys`, `/admin`, `/observatory` return HTML shell.
- `GET /ui` and `/ui/overview` return 404.
- `POST /mcp` `tools/list` still works.
- `GET /mcp/info`, `/healthz`, `/client/manifest.json`, `/v3/auth/whoami`, `/auth/login`, `/libraries` still hit their API/doc handlers.
- Login callback default `return_to` and logout redirect point to `/`.

Frontend tests:

- App renders at root router without `/ui` basename.
- Anonymous dashboard login points to `/auth/login?next=%2F` when loaded at `/`.
- Root navigation links are `/`, `/libs`, `/keys`, etc.
- Keys empty state and copy-once warning are visible.
- ACL role order is `reader`, `writer`, `admin`.

Manual browser check:

- Open `/` and confirm dashboard renders, no visible raw hidden text.
- Open all known UI deep links and confirm they render.
- Open `/ui` and confirm it is no longer a UI entry.
- Open `/mcp/info` and confirm JSON response still works.
