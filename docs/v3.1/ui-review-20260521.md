## Highest priority findings

### P0 — `/` is not the UI entry point yet

`GET /` currently returns `{"detail":"Not Found"}` while the app lives at `/ui/`.

Evidence: [`17-root-404.png`](ui-review-20260521/17-root-404.png)

Recommendation: make `/` the canonical and only UI entry point; `/ui/*` should be removed rather than kept as a compatibility alias.

### P0 — Deployment banner and hidden a11y text are visibly broken

Every screenshot shows raw text above the app:

- `instance ma3-v3-1-cand... commit ... deployed ... job ... base url ...`
- `ma3 Knowledge Observatory`
- `topic_kind Next Run Search Explain ... debug_candidates ...`

Root cause from local code inspection: `routes_ui.py` injects HTML with classes such as `deploy-banner`, `dep-cell`, and `sr-only`, but the Vite/Tailwind build does not include CSS for classes that only appear in the Python server file. Therefore `sr-only` is not hidden and the deploy banner is unstyled.

Evidence: all UI screenshots, especially [`02-anonymous-dashboard.png`](ui-review-20260521/02-anonymous-dashboard.png) and [`16-observatory.png`](ui-review-20260521/16-observatory.png).

Recommendations:

1. Move deploy identity rendering into the React app, fetched from `/healthz` or embedded as JSON.
2. Or add a tiny non-Tailwind static CSS block in `index.html` / `routes_ui.py` for `.deploy-banner`, `.dep-*`, and `.sr-only`.
3. Remove the SEO/test-only hidden keyword span from production UI, or make it truly hidden with inline style if it must remain.

### P1 — The library detail page is currently ACL-first, not knowledge-first

The “Library detail” page primarily shows ACL controls. The actual ma3 knowledge object is a placeholder: `First-page record preview placeholder for v3.1.`

Evidence: [`05-library-detail-acl.png`](ui-review-20260521/05-library-detail-acl.png)

Recommendations:

- Put library content first: search box, recent records, recent cases, ingestion/report CTA, and quality indicators.
- Move ACL into a secondary tab (`Records`, `Cases`, `Members`, `Settings`) or a right-side admin panel.
- Replace placeholder with real first-page records/cases before releasing v3.1 UI.

### P1 — Empty states and admin-only states need better guidance

Examples:

- Keys page shows an empty table and “Create key” only; it does not explain why no keys exist or what scopes will be available.
- `Create API key` modal has only a label field; no scope selector, expiry, or warning that the raw key is shown once.
- Observatory says “No status distribution available” without explaining whether that means no data, an API error, or the metric is not implemented.

Evidence: [`09-keys-page.png`](ui-review-20260521/09-keys-page.png), [`10-create-key-modal.png`](ui-review-20260521/10-create-key-modal.png), [`16-observatory.png`](ui-review-20260521/16-observatory.png)

Recommendations:

- Add explicit empty-state copy and next actions.
- API key creation should expose `scope_libraries` and `expires_at`, and state “copy now; this key is shown only once”.
- Distinguish “metric not implemented” from “metric is zero”.

## Additional UI improvement recommendations

### Navigation / information architecture

Current top-level nav: Dashboard, Me, Libraries, Keys, Observatory, Admin.

Suggested structure for agent users:

- **Search / Context**: primary entry to query ma3 knowledge.
- **Cases**: browse case graph and attached records.
- **Libraries**: manage membership and library data.
- **API keys**: issue and revoke keys.
- **Observatory**: ops metrics.
- **Admin**: global privileged tools.

Dashboard should answer “what can I do now?” with 3–5 task cards, not only link tiles.

### ACL UX / safety

Evidence: [`05-library-detail-acl.png`](ui-review-20260521/05-library-detail-acl.png), [`06-add-principal-modal.png`](ui-review-20260521/06-add-principal-modal.png)

Issues:

- Role dropdown order is `admin`, `reader`, `writer`; expected is `reader`, `writer`, `admin`.
- Role changes appear to save immediately from a dropdown; the screen does not show “saved”, “saving”, or rollback on failure.
- Red `Remove` buttons are visually dominant and placed on every row.
- Legacy token principals are shown as raw IDs without explanation.

Recommendations:

- Sort role options by privilege: reader → writer → admin.
- Add optimistic save status or require an explicit “Save changes”.
- Use a kebab/action menu or secondary destructive button for removal.
- Explain legacy principals and show display name + type badges.

### Admin console

Evidence: [`11-admin-page.png`](ui-review-20260521/11-admin-page.png), [`13-admin-audit.png`](ui-review-20260521/13-admin-audit.png), [`14-admin-backup.png`](ui-review-20260521/14-admin-backup.png)

Recommendations:

- Audit table needs filters by actor/action/library, relative time, and row expansion for payload JSON.
- Repeated `principal.assume_admin` rows should be grouped or visually de-emphasized.
- Backup tab displays `DEGRADED true` as ordinary text. This should be a red/yellow health badge with remediation text and links to doctor/health endpoints.
- Humanize labels: `archive_lag_seconds` → `Archive lag`, `basebackup_age_seconds` → `Base backup age`.

### Login / anonymous state

Evidence: [`01-auth-login.png`](ui-review-20260521/01-auth-login.png), [`02-anonymous-dashboard.png`](ui-review-20260521/02-anonymous-dashboard.png)

Recommendations:

- Anonymous dashboard should explain that ma3 uses `auth.zhilicon.com` SSO and API keys for agents.
- After moving UI to `/`, login `next` should default to `/`, not `/ui/`.
- Add a “continue as anonymous / public library reader” explanation if public libraries remain visible to anonymous users.

### Language and polish

The UI mixes English operational terms with Chinese library names. That is acceptable for data, but UI labels should be consistently English or consistently Chinese per user preference.

Recommendations:

- Add a locale toggle later; for now standardize system UI in one language.
- Replace raw snake_case labels with human names.
- Keep raw IDs visible but secondary, copyable, and monospace.

## Does serving the UI at `/` conflict with existing MCP design?

Short answer: **No, it does not conflict with the current MCP design, as long as `/mcp` remains a dedicated API route and the root UI catch-all is implemented carefully.**

Current verified routes on the candidate:

- `GET /` → `404` today.
- `GET /ui/` → UI shell.
- `GET /mcp/info` → MCP metadata works.
- `POST /mcp` with `tools/list` → works; tool schema includes `$defs.AgentAction`.
- `/healthz`, `/v2/*`, `/v3/*`, `/auth/*`, `/libraries`, `/client/*` are non-UI API/doc routes.

The ma3 MCP design contracts in `AGENTS.md` are about JSON-RPC tool payload schemas, `ma3_validate`, structured `-32602` errors, and keeping `/mcp` as Streamable HTTP JSON-RPC. None of those contracts require the browser UI to live under `/ui`.

### Safe migration plan for root UI

1. Change web build base:
   - `server/app/web/vite.config.ts`: `base: '/'`.
   - `server/app/web/src/main.tsx`: `<BrowserRouter basename="/">` or omit `basename`.
2. Serve the SPA at explicit root pages:
   - `/`
   - `/me`
   - `/libs`
   - `/libs/{id}`
   - `/keys`
   - `/admin`
   - `/observatory`
3. Keep API paths untouched:
   - `/mcp`, `/mcp/info`
   - `/healthz`
   - `/v2/*`, `/v3/*`
   - `/auth/*`
   - `/libraries*`
   - `/client/*`
   - `/metrics`
4. Remove `/ui`, `/ui/`, and `/ui/{page:path}` routes; they should return 404 after the cutover.
5. Update auth defaults:
   - `/auth/login` default `next="/"`.
   - `/auth/callback` default `return_to="/"`.
   - `/auth/logout` redirects to `/`.
   - `_safe_next` should allow root UI paths and continue rejecting external URLs.
6. Avoid an unsafe generic root catch-all:
   - Do **not** add `@router.get("/{page:path}")` before API routers.
   - If a catch-all is used, register it after all API routers and explicitly exclude API prefixes.
   - Prefer explicit SPA page routes over a broad catch-all.
7. Add regression tests:
   - `GET /` returns HTML shell.
   - `GET /ui/overview` returns 404 after the root cutover.
   - `POST /mcp` `tools/list` still returns tools.
   - `GET /mcp/info`, `/healthz`, `/client/manifest.json`, `/v3/auth/whoami`, `/auth/login`, `/libraries` still hit APIs.
   - Deep link `/libs/<id>` returns the SPA, while `/libraries/<id>` remains JSON API.

### Potential conflict to avoid

The only real risk is not conceptual MCP conflict; it is FastAPI/Starlette route shadowing. A static mount or catch-all at `/` can swallow `/mcp` or `/v3/*` if registered incorrectly. Route order and explicit exclusions are therefore part of the migration acceptance criteria.
